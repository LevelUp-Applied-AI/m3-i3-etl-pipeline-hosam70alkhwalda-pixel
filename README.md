# ETL Pipeline — Amman Digital Market

## Overview

This project implements an end-to-end ETL (Extract, Transform, Load) pipeline for the Amman Digital Market database.

The pipeline extracts data from a PostgreSQL database, transforms it using Pandas into customer-level analytics, validates data quality, and loads the results into a new database table and a CSV file.

The final output provides key business insights such as:
- Total number of orders per customer
- Total revenue generated by each customer
- Average order value
- Top product category per customer

---

## Setup

1. Start PostgreSQL container:
   ```bash
   docker run -d --name postgres-m3-int \
     -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres \
     -e POSTGRES_DB=amman_market \
     -p 5432:5432 -v pgdata_m3_int:/var/lib/postgresql/data \
     postgres:15-alpine
   ```

2. Load schema and data:
   ```bash
   docker exec -i postgres-m3-int psql -U postgres -d amman_market < schema.sql
   docker exec -i postgres-m3-int psql -U postgres -d amman_market < seed_data.sql
   ```

3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

## How to Run

Run the ETL pipeline using:

```bash
python etl_pipeline.py
```

## Output

The pipeline generates two outputs:

1. PostgreSQL Table: `customer_analytics`
   - Contains customer-level aggregated metrics.

2. CSV File: `output/customer_analytics.csv`
   - Columns:
     - customer_id
     - customer_name
     - city
     - total_orders
     - total_revenue
     - avg_order_value
     - top_category

This dataset can be used for business reporting, dashboards, and further analysis.

---

## Quality Checks

The pipeline includes data validation to ensure data quality and reliability:

- No null customer IDs or names  
  Ensures all records are identifiable and usable.

- Total revenue must be greater than zero  
  Prevents invalid or empty financial records.

- No duplicate customer IDs  
  Guarantees one row per customer.

- Total orders must be greater than zero  
  Ensures only active customers are included.

- Data cleaning rules applied during transformation:
  - Excludes cancelled orders (status = 'cancelled')
  - Filters out suspicious quantities (quantity > 100)

If any critical validation fails, the pipeline raises an error and stops execution.
